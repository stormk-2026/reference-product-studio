# 注册登录与服务器部署

本地默认维持单用户模式。公网必须启用应用认证，Compose 已为 Web 和 Worker 设置 `STUDIO_AUTH_ENABLED=1`。可信代理模式仅可在应用端口绑定回环、前方 Nginx 覆盖 `X-Real-IP` 时启用；不能将 8765/18765 直接开放公网。

## 初始化与升级

1. 确认所有账号无排队或运行任务，执行一致备份。保持旧的 Nginx Basic Auth，直到新应用验证通过。
2. 使用新镜像，在私有文件中准备两行：主账户用户名、密码。文件权限 600；不要写入镜像或仓库。将文件以只读方式挂载到一次性管理容器，执行 `python -m studio.manage_accounts --bootstrap-owner-file /run/owner-login.txt`。已存在主账户时不会覆盖密码。
3. 主账户继续使用根目录的原数据库和资产。普通账号初始化独立数据库，不共享历史；无需移动或复制旧素材。
4. 启动新 Web/Worker；验证匿名 API 返回 401，登录后可读主账户旧记录，新账号列表为空、额度为 3。确认无误才移除站点 Nginx Basic Auth 并 reload。
5. 验证 HTTPS 注册、登录、登出，确认其他站点正常。回滚时先恢复 Basic Auth，再恢复旧服务，防止意外公开旧单用户 API。新账号数据不可删除。

## 密码重置

在服务器私有终端进入运行中的 Web 容器：

```sh
docker compose -f deploy/compose.yaml exec web python -m studio.manage_accounts --reset-password studio
```

终端输入新密码两次，不回显，不把密码放进命令参数。重置撤销该账号所有会话。其他用户名使用相同命令。首版不提供邮件或短信找回。

## 配额和边界

普通账号共 3 张 AI 图片，含白底、混图、工业草图和宣传背景；每张扣 1 次，首张样稿也计次。Kimi 起草/润色、本地抠图和下载不扣图片额度；普通账号每日所有任务合计最多 20 次。提交即预占，明确失败返还，结果未知暂占用且不自动重试。批量必须整体有足够额度，重复确认同批次不会重复扣额。主账户不受次数限制。

注册按 IP 限速，并非实名认证；不保证一个人不能注册多个账号。没有充值/付费/自动续额功能。上传与历史保留在本人空间，其他账号（含主账户）无法通过 Web 读取；站点管理员仍拥有服务器运维权限。

## 数据、备份与后续迁移

根目录 `accounts.db` 保存账号、密码哈希和会话；主账户仍用 `studio.db`，普通账号位于 `users/<随机ID>/studio.db`。数据库 ID 只由服务端生成。OSS 对象不可匿名访问，通过账号空间解析资产 ID。

`python scripts/backup.py --output /backups` 同时备份所有账号和资产，备份会话被清空，恢复后必须重新登录。账号密码哈希属于敏感运行数据，备份仅保存在私有目录，权限 600。未来修改 workflow schema 时须对根数据库及所有 users 子目录执行迁移，不能只升级根数据库。
