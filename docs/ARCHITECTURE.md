# 架构方案 · M0 草案

## 技术选择与依赖

Python 3.11 + uv；FastAPI / Pydantic；SQLite + SQLAlchemy + Alembic；Jinja2 + 最少量原生 JavaScript；Pillow；pytest + Ruff。不引入大型前端框架。应用与 Worker 为两个本地进程，共享 SQLite 与本地资源目录。依赖版本在 M1 安装验证后锁定，不预造 lock 文件。

依赖方向：Web → service → domain；provider adapter、repository、storage 实现 domain/service 定义的接口。domain 不导入 FastAPI、SQLAlchemy 或具体模型 SDK。Web 只校验请求、构建响应，业务编排在 service。

建议目录：`src/studio/{domain,services,providers,repositories,storage,web,worker}`，模板和集中中文文案位于 web；`tests/{unit,integration,fixtures}`；`data/{assets,tmp,exports}` 默认不入 Git。

## 最小领域模型

| 对象 | 必要数据与约束 |
| --- | --- |
| Asset | 随机 ID、相对路径、SHA-256、真实格式、像素尺寸、字节数、用户声明来源、上传时间、fixture 标识 |
| Analysis | 输入 ID、字段值与证据状态、关联图片、遮挡/待确认项、补充信息、版本；用户修正保留，不由再分析覆盖 |
| SceneRecipe | 全部场景字段、unknown/null、每项继承/修改/忽略、用户覆盖值、保留/排除项、版本、源参考 ID |
| Job | 操作类型、不可变输入快照、幂等键、状态、阶段、worker 租约、外发授权快照、供应商请求 ID、错误分类、时间 |
| Candidate | 结果 Asset、A/B/C 与子模式、输入与分析/Recipe 快照、要求、provider/model、模板版本、seed、外部 ID、时间/耗时、实际用量、费用和依据、fixture、处理记录、收藏标记 |
| Evaluation | Candidate 与比较组关联、人工评分/文字、失真细节、返工时间/操作、失败原因、评价时间；未评价不填默认优良 |

SQL 表只做必要关联；结构化快照可用 JSON 保存并通过 Pydantic 校验。数据库迁移用 Alembic；不靠启动时静默更改生产表。输入快照不可变，编辑产生新版本，再生成指向新快照。

## 模型接口与能力检查

只实现一个真实多模态理解适配器、一个真实图像适配器及独立 Fixture 实现。服务商未选定，暂不决定端点、模型名称或价格。接入前查用户配置和官方文档，记录文档来源、日期、精确模型和能力。

能力声明至少包括：理解、多图、图像生成、图像编辑、蒙版编辑、分割、异步任务查询、seed、返回格式及可安全下载的域名。请求编译前验证所需能力；不支持即返回带原因的 unsupported，不静默退化。

Fixture 输出为带明显“测试夹具 / 非模型生成”标记的固定文本与有效测试图，只证明链路。输入、Job、Candidate、下载与导出均带 fixture 标识。不得将 Fixture 的固定描述称为对用户图片的真实识别。

## 工作流

- A：上传与补充 → 分析 Job → 结构化分析/资料 → 独立正面、背面、实验示意 Job。背面输入证据决定“观察候选/设计假设”标签；实验警示不可由模型覆盖。
- B1：透明图/蒙版检验 → 背景生成 → Pillow alpha 合成 → 结果与变换记录。先支持用户透明图替代路径；不凭空宣称分割能力。记录位置、缩放、重采样、边缘、调色/光照；默认不修改主体颜色。
- B2：原图 + 明确重绘要求 → 编辑请求 → 与原图对照及人工特征检查。
- C1：商品 + 参考 + 简短要求 → 编辑请求。
- C2：参考分析 → Recipe 编辑/选择 → 编译约束 → 按用户选择传原参考或仅文字 → 编辑请求。忽略字段不进入继承约束，排除项明确编译为禁止带入要求。比较组固定商品和参考，保留每次调用及返工差异。

## 持久化与恢复

状态：`queued → running → succeeded | failed | interrupted | outcome_unknown`。unsupported 为提交前能力错误，不能产生假成功。Worker 用 SQLite 条件更新原子领取任务，避免多个进程领取同一 Job；记录心跳和租约。

调用外部服务前先持久化“即将发送”阶段。已发送或不能确定是否发送的任务，在超时/崩溃后记 outcome_unknown；明确尚未外发的任务可记 interrupted。供应商支持查询时使用已保存 ID 恢复；不支持时保留未知，不自动再发生成。响应与本地提交间崩溃也不能假定失败或成功。

同一表单提交带幂等键，数据库唯一约束保证重复点击返回已有 Job；人工主动再生成用新键，并显示可能重复费用。真实生成默认不自动重试；查询/下载恢复与新生成分开。预算按调用前保守上限预留，价格依据缺失时不能声称金额限制可被精确执行，需用户提供可接受的调用上限和供应商侧费用限制。

文件先写 tmp，校验后原子移动到 assets，再关联数据库；恢复时识别未关联文件，不伪造 Candidate。相同内容可记录 hash，但不能因为文件相同自动合并不同授权或实验记录。

## 本地安全

绑定 127.0.0.1，Host 仅允许本地名称/地址，变更请求验证 Origin 和 CSRF token。UI 不含密钥；配置与真实资源被 Git 忽略。日志采用字段白名单，避免原始授权头、供应商响应、带签名 URL 泄漏。

上传设置字节/像素上限，只接受明确列入白名单的静态光栅图片，MIME、文件签名、Pillow 解码联合检查；文件名不用作存储路径，拒绝 SVG/HTML 等主动内容。资源访问通过数据库 ID 映射、根目录 containment 检查，不提供任意路径/URL 下载接口。

模板默认转义，原生 JS 用 textContent 渲染模型文本，不执行模型生成 HTML。模型提示明确图中文字是数据，不能改变流程或授权；结构化响应经 schema 校验。原图外发页列出接收方、模型和全部资源缩略图，授权绑定输入版本。

优先安全解码供应商内联图片；如必须下载 URL，依据官方来源限制 HTTPS 域名、端口、DNS/IP、跳转、时限和大小，拒绝内网/回环/链路本地地址，不允许用户注入下载目标。出口约束不足时明确阻塞此返回方式。

## 验证与范围

M1 用离线 Fixture 验证工作流和确定性处理；M2 才验证外部协议与视觉可行性。M3 完善恢复、配方复用与评价操作，但 M1 即保证必要安全、幂等、证据标签与持久化，不延后基础防护。无账户管理、管理平台或多余 CRUD 页面。
