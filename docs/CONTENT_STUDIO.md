# 宣传图文：App 展示与商品种草

第三个独立工具，沿用 Storm Studio 的私有素材、任务、历史和下载能力。

## 两套方案

- **App 展示**：提供真实截图，填写 App 名称、真实功能、适用人群及可选的真实体验。内容围绕价值、功能和操作流程展开。
- **商品种草**：提供商品实拍或已制作的展示图，填写商品名称和已知卖点。内容围绕商品、外观细节和使用场景展开。建议使用透明 PNG 或清晰白底商品图，便于与生成的视觉背景融合。

每次 1–6 张素材，每张最多 15 MB。选择 3–6 页，固定 3:4（1152×1536）；提供清爽、深色、奶油三种风格及强调色。

## 流程与费用

1. 上传图片或从资产选择，填写真实资料。
2. 点击 AI 起草，预览将发送的图片、文字、接收方与一次调用范围；确认后通过 Kimi 起草。也可以完全手写，不调用模型。
3. 修改每页标题、正文、素材选择，以及独立的发布标题和正文。核对提示不能当作事实核验报告。
4. 可选 Kimi 二次润色：仅改写现有文案，保留原版供对照与恢复；润色也要单独预览、授权一次调用。
5. 预览 Seedream 首页视觉调用，确认后生成首页样张。模型负责场景、图形与光影，程序把原始素材及用户确认的文字叠入画面，避免模型改写 App 界面、商品 Logo 和文案。
6. 首页满意后，预览余下页每页提示词与最大调用次数，再一次授权批量任务；每页独立调用一次，使用首页视觉背景作风格参考。失败或结果未知不自动重试。
7. 下载各页 PNG 或整套 ZIP，复制发布正文。历史作品可恢复配置与内容；新建任务保留历史。

图片调用 Seedream 生成视觉背景；每张最终成图由 Pillow 将原图等比叠放并排版文字，原图不做生成式重绘。商品输入若为不透明白底，白底仍可能作为照片矩形保留；透明 PNG 更利于融合。标题区和页脚区使用半透明面板保证可读性。文字溢出明确失败，不能截断后冒充完成。不自动发布，也不能保证 AI 背景不会生成多余细节，必须人工查看。

文案只能依据提供的资料与可见截图；不联网补充产品事实，不编造体验、性能、销量、价格、竞品或技术栈。没有真实体验就不要求第一人称背书。仍需用户核对，不能声称 AI 已认证。

## 实现

`CONTENT_COPY`：签名确认 → Worker → Kimi 结构化文案 → analyses。

`CONTENT_POLISH`：已确认文案 + 可选润色方向 → 签名确认 → Kimi 文本调用 → 新 analyses；原版保留在任务请求里。

`CONTENT_SCENE`：已确认逐页文案 → 签名确认 → Seedream 生成一页背景 → 本地叠放原始素材与文字 → candidates 与资产存储。首页通过后，余下页共享签名批量预览和幂等键，每页单次调用；保存首页视觉图层供后续页风格参考。结果可单页下载或整套 ZIP。

`CONTENT_RENDER`：旧版本地排版任务仅作历史兼容，不再是新建图文的默认路径。资产共享本地或私有 OSS。

前端不显示内部模式代码。原白底、场景混图、工业草图的模型链路与提示词不变。服务仍是单用户私有测试部署。

中文字体：macOS 使用系统 PingFang / STHeiti；Linux 使用 `fonts-noto-cjk`，两个 Dockerfile 均安装此包。Linux 本地启动前可运行 `sudo apt-get install fonts-noto-cjk`。字体缺失会明确报错，不用缺字方框替代。
