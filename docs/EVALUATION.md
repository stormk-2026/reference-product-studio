# 验收与评估标准

状态：评估协议草案；没有执行模型评估，不存在真实质量结论。

## 分开报告

1. 工程：入口、数据、任务、下载、恢复、安全和测试是否完成。
2. 模型：Fixture / 真实调用 / 不支持 / 未验证，记录精确模型和输入。
3. 视觉：由用户查看实际结果评定；自动化绿灯不证明保真或可生产。

## 离线关键规则：先 RED，再 GREEN，再 REFACTOR

- 无背面输入时禁止“背面还原”；未知尺寸不得补为测量；纸样警示在页面与导出存在。
- 证据状态合法；用户确认与模型观察不混淆；Recipe 忽略/修改和 unknown 保留正确。
- 不支持多图、蒙版或编辑的供应商不能静默退化。
- 幂等提交仅产生一个 Job；并发领取只产生一个执行者。
- 外发后超时与崩溃不自动重试付费，不冒充 failed/succeeded；查询只在能力支持时执行。
- B1 用可验证 alpha 测试图检查合成、位置、缩放及背景泄漏；重采样等处理必须留记录。
- 拒绝错误 MIME/解码、过大文件/像素、路径穿越、不允许的 Host/Origin、缺失 CSRF；模型 HTML 不执行。
- Fixture 从输入到输出、下载、导出均可识别；无费用依据时 unknown；密钥不出现在响应与导出。

测试分目录及标记：unit、integration（离线真实 DB/文件）、fixture workflow；真实模型评估单独命令、显式授权、默认不被 pytest 收集执行。RED/GREEN 记录真实命令与结果，不补写虚假的失败历史。

## A 视觉评估

至少准备：可见正面、正背面成组、遮挡/细节不足三类案例，可复用素材。逐项检查可见结构识别、遗漏、观察/推测/未知分类、不可见信息是否虚构；查看技术图导出是否有效；记录修改项。实验纸样只评价表达与警示，不评价准确测量或可生产能力。

## B 视觉评估

B1、B2 分开记录：要求是否完成，轮廓/颜色/文字/图案/结构是否变化，透明边缘、阴影与背景是否协调。B1 可在对齐且已知变换后做确定性辅助检查；B2 不用像素差或 CLIP 分数宣称保真。人工逐项勾选通过/失败/无法判断并写原因。

## C 可比实验

同一商品与参考构成一个比较组；尽可能用相同图像模型、画幅和保留要求，记录不能控制的差异。比较 C1、C2 原参考+配方，以及有预算时 C2 仅文字策略；不把调用次数不同隐藏成相同成本。

两轮：首次出图；再对同一个场景元素提出修改，记录修改步骤、调用、耗时、费用依据和人工返工分钟数。维度独立：商品保真、参考符合度、可控性、视觉可用性。可用 1–5 分加具体理由，未评填 null；不汇成未经解释的“最佳分”。用户评价作为验收记录，模型复检只作为辅助意见。

## 每次实验记录

案例 ID、输入 hash/来源声明/fixture、模型与模板版本、输入快照、策略、请求 ID、耗时、用量、费用/unknown、结果资源、失败分类、人工评价、返工记录。保留所有尝试（含失败和 outcome_unknown），不只挑成功图。

真实素材由用户提供且显式授权外发。至少需要一组服装图、一张透明商品图或可用蒙版、一张参考场景图；可以同一组覆盖多个功能。尚未收到素材，样例数量与模型费用在 M2 前确定。
